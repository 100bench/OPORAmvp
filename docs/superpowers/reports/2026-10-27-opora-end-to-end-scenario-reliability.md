# Опора: проверка полных сценариев на Samsung

Дата: 28 октября 2026 года. Ветка: `codex/opora-mvp`.

## Статус

**Приёмка пилота не завершена.** Код и тестовый контур исправлены, но полные
маршруты Яндекс Go и Auto.ru на физическом Samsung ещё не пройдены до безопасной
финальной границы. Голосовые прогоны пользователя и 20 замеров тёплой задержки
во время полных маршрутов также отсутствуют. Синтетические деревья не заменяют
эти проверки.

## Зафиксированная конфигурация

| Компонент | Значение |
| --- | --- |
| Телефон | Samsung SM-N975F, Android 12, ADB `RF8MA183F5A` |
| Яндекс Go | 5.98.4 (`50128706`) |
| Auto.ru | 26.39.0 (`100630`) |
| Модель | `gpt-6-luna` через существующий OpenAI proxy на Mac/VPN |
| Prompt | `planner_v1.md`, SHA-256 `108b4611e17445f9de2ebe9bff3975c92de51766c61931adffa9df44ede45ac4` |
| Установленный debug APK | SHA-256 `62e83055cfae74ad47dfbd7e7651f2f59a0f2878025c1a4f69f2452e366de4e9` |
| Последний пересобранный debug APK | SHA-256 `89a90f5eae41900acba0eec2e5553a7bd63748abab03e56d3e6941cdbbeeed58` |

APK установлен на Samsung. `adb reverse tcp:8787 tcp:8787` активен, `/health`
proxy вернул `ok=true, key_configured=true`, разрешение overlay выдано,
`ScreenReaderService` включён. Тестовый ввод текста и экспорт обезличенных
деревьев и закрытый семантический probe доступны только в debug и защищены
`android.permission.DUMP`; в release manifest и DEX probe отсутствует.
Установленный и повторно собранный APK имеют разные бинарные хеши, но
соответствуют одному исходному коммиту; живые наблюдения относятся к
установленному APK.

## Автоматические проверки

- `./gradlew testDebugUnitTest assembleDebug assembleRelease --rerun-tasks` —
  успешно на текущем коммите: 515 тестов, 0 ошибок, 3 ожидаемо пропущенных
  opt-in live-теста. Сборка из чистого checkout с тем же patch также прошла.
- Replay — 23 строки, 10 сохранённых обезличенных реальных деревьев и
  10 явно синтетических fixtures. Яндекс Go: старт Такси, пустое назначение,
  два результата «Парк Победы» и финальный экран с честной потерей сигнала
  после обезличивания. Auto.ru: вход в продажу, две одинаковые кнопки,
  категория и пустая форма госномера. Для каждой строки с guidance обязателен
  ровно один подсвеченный target внутри viewport; неоднозначность и
  неактивная кнопка не дают вводящего в заблуждение кольца.
- Локальные auth, финальная передача пользователю и оба варианта popup
  проверены на синтетических поверхностях без вызова модели.
- Новый debug-приёмник передаёт русский тестовый текст в тот же обработчик,
  что карточка приложения, и сам не добавляет запись или логирование запроса.
  Обычное сохранение сессии действует: guidance может сохранить запрос как
  `session.goal` в зашифрованной `ResumeCapsule`. После пробы нужно остановить
  сценарий; остановка, завершение и безопасная финальная передача удаляют капсулу.
  Просроченная капсула удаляется при загрузке после 30-минутного срока
  возобновления, а не фоновым таймером. Для проб допустим только неличный текст.
- Дополнительный debug probe возвращает из текущего дерева только фиксированные
  коды общих подписей, тип совпадения и числовую геометрию. Он не выдаёт
  неизвестные подписи, значения полей, ID или имя пакета, а локальная safety
  проверка подавляет цели на защищённом экране. Приёмник ничего не нажимает.
- Итоговая проверка кода выявила два геометрических края: popup за пределами
  активного окна и допустимую частично видимую цель с исходными bounds за
  пределами окна. Оба исправлены общим правилом: popup использует общую
  пригодность цели, а рисуемые границы обычной цели и popup ограничены активным
  viewport. Независимая повторная проверка приняла исправление.

## Живая проверка OpenAI

Последний оплачиваемый прогон после исправлений: 20 фактических безопасных
вызовов на обезличенных fixtures, 20/20 пригодных шагов, 0 format-repair,
0 ошибок safety; planner p50 **2466 мс**, p95 **4476 мс**. Четыре вызова
использовали реальное обезличенное дерево поля адреса; остальные 16 — явно
синтетические деревья. Это время вызова планировщика, не задержка отображения
подсказки на Samsung.
Новые реальные деревья Такси/Auto.ru были добавлены после этого платного
набора; результат 20/20 не переносится автоматически на их живые ответы.

Оценка `chars/4` дала около 25 384 входных и 332 выходных токенов. Она не
включает schema/tool envelope, не является счётом провайдера или суммой оплаты.
Точные billed usage и стоимость этим тестом не измерены.

История кандидатов сохранена для честного сравнения: до уточнения языкового
prompt набор дал 18/20; после него и до локального завершения одношагового
ответа — 17/20. Диагностика трёх провалов показала короткий ответ с нужным
полем, но без предложения дальнейшей помощи. Теперь одношаговый ответ локально
добавляет «Чем ещё помочь?», если модель не предложила помощь сама. Для
сохранения естественного ответа повторная фраза не добавляется.

## Проверка на телефоне

На прежнем APK один английский текстовый пробный вопрос получил две ошибки
проверки формата. Безопасный код причины в повторном русском пробном запросе
показал `LANGUAGE`: модель иногда вставляла латинское название приложения,
которого нет среди подписей UI-дерева. Контроль схемы и transport прошёл.
Prompt и единственный разрешённый format-repair теперь явно запрещают такие
латинские слова; языковой валидатор не ослаблен. На том же Samsung три русских
одношаговых вопроса подряд после этой правки прошли с первого вызова.
Операторские замеры до первого полезного текста: cold 4449 мс, warm 2888 и
3800 мс; TTS начинался позже. Эти три наблюдения относятся к более раннему APK
и **не** составляют требуемую выборку 20 тёплых замеров полного маршрута.

На текущем Samsung debug probe нашёл на старте Такси одно однозначное действие
«Куда едем?» (два текста сводятся к одному нажимаемому элементу, index 45,
bounds `[45,1515,1031,1673]`). Нажатие по центру, полученному из дерева,
открыло пустое поле назначения «Куда поедете?» (index 45,
`[187,422,806,480]`). Текстовая цель в Опоре дошла до подтверждения
«Начать»; эта кнопка самой Опоры была найдена по её ID и подписи и нажата.
Подсветка после нажатия появилась через 82 мс. Первые два запуска после
переустановки дали 6927 и 5142 мс до карточки подтверждения (cold);
один переход после ввода публичного запроса дал 2623 мс до полезного ответа.
Это отдельные шаги, не полный маршрут и не warm p50/p95.

Первая попытка ввода `Red%20Square` была некорректной; пользователь заметил её
на экране. Ввод кириллицы через обычный `adb input text` на этом Samsung
завершился ошибкой Android, поэтому пользователь сам ввёл публичное
«парк победы». Дерево показало **две разные точные цели** с названием
«Парк Победы». Это реальная неоднозначность: локальный replay возвращает
Ambiguous и не рисует кольцо. Для обратимого теста разработчик явно выбрал
верхнюю из двух точных публичных строк; Опора не объявляла её единственной.

После этого экран Яндекс Go оказался на финальном шаге заказа. На живом
Samsung локальная проверка вернула `SAFE_HANDOFF/FINAL_ACTION`, фактическое
состояние сценария и видимая карточка Опоры — `SAFE_HANDOFF`; подсветки цели
и вызова планировщика не было. Заказ не подтверждался. Обезличенный fixture
этого экрана теряет составной финальный сигнал и честно даёт NotFound в
replay; он **не** считается доказательством финальной защиты. Живое наблюдение
и синтетический положительный тест safety указаны отдельно. Полного
самостоятельного ведения через неоднозначный выбор результата мы не проверили.

В Auto.ru разработчик закрыл нижнее окно через однозначную область закрытия,
нашёл «Продать» и дошёл до двух разных точных кнопок «Разместить объявление».
Локальный replay возвращает Ambiguous без подсветки. Для обратимого теста
разработчик явно выбрал верхнюю кнопку, затем однозначную категорию
«Легковые». На пустой форме «Госномер» локальный production resolver выбрал
левое поле `[45,433,742,613]`, а не соседнее поле региона; неактивная
«Продолжить» дала NotActionable без кольца. Госномер, VIN, телефон, пароль и
SMS-код не вводились и не читались, публикации не было. Без личных данных и
надёжной кнопки пропуска маршрут останавливается на этой форме.

Живой запрос модели на форме Auto.ru не выполнялся: локальный аудит точного
DTO не смог подтвердить безопасность восьми неизвестных статических подписей
и трёх внешних ID без чтения их содержимого. Это ограничение проверки, а не
утверждение, что в полях есть личные данные. Подсветка Auto.ru пока доказана
детерминированным replay, а не живым ответом модели.

## Оставшиеся блокирующие пункты

1. Пройти Яндекс Go целиком как пользователь Опоры, включая выбор между
   несколькими результатами, и собрать 20 warm задержек. Разработчик уже
   физически дошёл до корректного финального handoff, но выбор результата
   был сделан как отдельное тестовое решение.
2. Продолжить Auto.ru после ввода пользователем своего госномера и дойти до
   VIN, следующих форм и безопасной границы публикации. Живой запрос модели
   на текущем экране запускать только после проверки отправляемого DTO.
3. На живых экранах проверить popup с крестиком/без него и настоящий auth,
   когда они воспроизводятся. Синтетические проверки уже есть.
4. Получить не менее 20 warm text-to-render замеров во время полных маршрутов
   и сравнить p50 ≤3 с, p95 ≤5 с. Несколько холодных/отдельных шагов и planner
   latency не удовлетворяют этому критерию.
5. Пользователь проводит четыре голосовые проверки ниже; запись речи не нужна.

### Голосовые кейсы для пользователя

1. Откройте стартовый экран Яндекс Go и скажите: «Помоги заказать такси до
   нужного адреса». Следуйте подсказкам до безопасной финальной передачи от
   Опоры перед подтверждением заказа. Проверьте, что финальная кнопка не
   подсвечена и Опора не предлагает её нажать. Заказ в рамках проверки не
   подтверждайте. Отметьте неверную подсветку, сообщение об авторизации или
   паузу; адрес и запись голоса не присылайте.
2. Откройте Auto.ru и скажите: «Помоги продать автомобиль». Пройдите госномер,
   VIN и следующие формы до безопасной финальной передачи от Опоры перед
   публикацией. Проверьте, что финальная кнопка не подсвечена и Опора не
   предлагает её нажать. Объявление в рамках проверки не публикуйте. Личные
   значения не присылайте.
3. На обычном экране спросите: «Что сейчас на экране?» Ответ должен быть
   коротким и предложить помощь с дальнейшей целью; прежний маршрут завершается.
4. На другом экране спросите: «Куда мне здесь нажать, чтобы продолжить?» Если
   однозначная кнопка есть в UI-дереве, она подсвечивается; иначе Опора честно
   объясняет, что именно не удалось определить.

Для каждого кейса нужны только «прошёл/не прошёл», экран и шаг сбоя, а также
примерная задержка от окончания речи до первой полезной подсказки. Содержимое
личных полей и аудио не нужны.
